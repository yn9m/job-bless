# job-bless

Агент для поиска работы на hh.ru: сам собирает вакансии, оценивает их
нейросетью на соответствие вашему резюме, откликается на подходящие и пишет
сопроводительные письма. Всё настраивается через веб-интерфейс.

HH работает по одной схеме локально и на сервере: **job-bless → Docker → Camoufox → hh.ru**.
Вход выполняется в браузере внутри панели; токены API hh не нужны.
Можно запустить на Linux-сервере: вход в HH и Google открывается прямо в веб-панели,
а браузеры и расписание работают на сервере. [Развёртывание и схема](docs/server.md).

---

## Что умеет

| | |
| --- | --- |
| **Сбор вакансий** | Проходит по страницам поиска и складывает карточки в базу |
| **Оценка** | Сравнивает каждую вакансию с профилем кандидата: балл 0–100 плюс обоснование |
| **Отклики** | Откликается на всё выше порога — вручную по кнопке или автоматически |
| **Сопроводительные письма** | Если вакансия просит письмо, пишет его и всё равно откликается |
| **Сообщение работодателю** | После нового отклика пробует отправить короткое сообщение в чате hh.ru; результат виден во вкладке «Отклики» |
| **Профиль кандидата** | Резюме с hh.ru плюс ваш рассказ об опыте, сжатые отдельной моделью |
| **Имитация активности** | Медленно листает hh.ru параллельно всему остальному, чтобы аккаунт выглядел живым |
| **Обновление резюме** | Поднимает резюме в поиске по расписанию |
| **Ограничение нагрузки** | Свои рейт-лимитеры, чтобы hh.ru не отвечал капчей |

Чего **не** умеет: отвечать на анкеты и тесты работодателя — такие вакансии
пропускаются со статусом `skipped_questions`.

## Готовая сборка для Windows

Для HH установите и запустите **Docker Desktop с Linux-контейнерами**. Приложение само
подготовит контейнер Camoufox при первом запуске; это требует интернета и нескольких минут.
Повторные запуски используют готовый образ. При выходе приложение останавливает свой контейнер.

В полном комплекте `job-bless-Setup.exe` уже находятся Python, Node.js,
AIStudioToAPI и Camoufox. Установите приложение, откройте **«Действия»** и
нажмите **«Подключить Google AI Studio»**. После входа в Google приложение
само запускает локальный сервис, проверяет ответ модели и сохраняет подключение.
При следующем запуске сохранённый вход используется автоматически.
Для первого подключения Google скачивать компоненты не требуется; интернет нужен
для Google, генерации ответов и hh.ru. Свой API можно подключить через настройки.

Данные полного комплекта хранятся в `%LOCALAPPDATA%\job-bless\data`, отдельно
от программы. В меню есть **«Завершить работу»**; повторный запуск открывает
уже работающее приложение. Переносной вариант запускается через `Start-job-bless.vbs`.

Сборка установщика: `python scripts/build_windows_bundle.py` на Windows x64
с Python 3.13, uv и компилятором .NET Framework. Компоненты скачиваются только
при сборке, проверяются по SHA-256 и повторно используются из кеша.
Версии закреплены в `packaging/components.json`; условия использования
компонентов перечислены в `packaging/THIRD_PARTY_NOTICES.md`.

## Требования для запуска из исходников

Для сервера GitHub Actions публикует готовые образы приложения, HH и Google AI Studio
в GHCR. `docker-compose.yml` скачивает их; сборка на production не нужна:

```bash
python3 scripts/configure_server.py --generate-password
docker compose pull
docker compose up -d --no-build
```

Для локальной сборки текущего кода используйте `docker compose -f docker-compose.yml -f compose.build.yml up -d --build`.
Для серверного варианта на Docker локальные Python-зависимости и Chrome не нужны.
Для нескольких пользователей предусмотрен отдельный режим с входом через **Clerk**:
у каждого своя БД, резюме, вакансии, настройки, задачи и браузеры HH/Google.
См. [многопользовательскую установку и перенос прежних данных](docs/multiuser.md).
См. [инструкцию для сервера до 4 ГБ ОЗУ](docs/server.md). Описанный ниже запуск
из исходников и готовая Windows-сборка сохраняются.

- **Python 3.11+**
- **[uv](https://docs.astral.sh/uv/)** — установка зависимостей
- **Docker Desktop с Linux-контейнерами** (Windows) или **Docker Engine** (Linux) — для HH
- **Аккаунт hh.ru** с резюме
- **Доступ к нейросети** по API одного из стандартов: OpenAI, Google Gemini или
  Anthropic. Проект писался под локальный мост AIStudioToAPI
  (`http://localhost:7860`), но подойдёт любой совместимый эндпоинт. Без
  нейросети работает только сбор вакансий.

## Установка

```bash
make install
```

Ставит виртуальное окружение и зависимости. Отдельный браузер Playwright
скачивать на компьютер не нужно — Camoufox устанавливается внутри Docker.

## Запуск

```bash
make web-local
```

Запустите Docker и выполните команду выше. Приложение само подготовит браузер и выведет
личную ссылку на панель; откройте её в браузере. Ctrl+C завершает приложение и его контейнер HH.
Для постоянной работы и доступа по локальной сети можно запустить весь стек через
[Docker Compose](docs/server.md).

## Первый запуск: пять шагов

### 1. Войти в hh.ru

В разделе «Действия» нажмите **«Открыть браузер»** в карточке HH. Войдите на странице
HH внутри панели: пароль, SMS и капчу вводите прямо на сайте. Вход определяется
автоматически; «Я вошёл» запускает повторную проверку. Сессия сохраняется в
`data/hh-session.json` и восстанавливается после перезапуска приложения или контейнера.
При переходе со старой версии на Chrome войдите в HH заново.

### 2. Выбрать резюме

После входа все резюме аккаунта hh.ru импортируются автоматически. На вкладке
**«Резюме»** выберите активное. Кнопка **«Обновить все резюме»** справа вверху
заново читает сохранённые резюме с hh.ru и находит новые резюме аккаунта.
Поисковые запросы, ваши заметки и выбранное активное резюме сохраняются.
Если текст изменился, готовый профиль будет помечен устаревшим.

### 3. Задать запрос и рассказать про опыт

Для сбора вакансий без резюме выберите **«Без резюме»** в карточке **«Режим поиска»**
на странице «Действия». Запрос задаётся через «Настроить поиск» и сохраняется отдельно
от запросов резюме. Вход в HH, импорт и перезапуск приложения не меняют этот выбор.
Сохранённые резюме остаются доступны; выберите одно из них, чтобы включить оценку
соответствия и отклики по оценке.

**«Собрать вакансии»** последовательно читает все доступные страницы выдачи с паузами
из раздела «Ограничение нагрузки». Сбор заканчивается, когда больше нет следующей
страницы, либо по кнопке «Стоп». Старые настройки `scroller.max_pages` и YAML
`max_pages` больше не применяются. Уже прочитанные страницы сохраняются сразу;
повторный сбор обновляет вакансии по ID, а не создаёт дубликаты. При капче, ошибке
или зацикливании переходов сбор прерывается.

Из карточки выдачи сохраняются ID и ссылка вакансии, название, компания, зарплата
текстом, город/адрес, формат работы, опыт и краткий фрагмент обязанностей — если
они есть в выдаче. Также сохраняются время обнаружения, URL поиска, страница,
позиция и связь с запуском поиска (и выбранным на момент запуска резюме).
После сохранения карточек сборщик последовательно открывает каждую вакансию
в отдельной вкладке и сохраняет полное описание, ключевые навыки, дату публикации,
признак архива, обязательность сопроводительного письма и наличие теста/анкеты HH.
Используются данные самой страницы; отклик или форма отправки не запускаются.
Паузы между открытиями действуют и здесь. Из-за чтения каждой вакансии сбор идёт
дольше, чем разбор одной выдачи. Подробности сохраняются сразу после каждой вакансии.

Новые поля доступны в блоке «Подробности вакансии» и CSV. Полное описание и навыки
используются при последующей оценке резюме (в пределах лимита текста для модели).
У ранее собранных вакансий подробности появятся при следующем обнаружении в поиске;
старые оценки автоматически не пересчитываются. Если HH не отдал признак, он остаётся
неизвестным, а не превращается в «нет». Отсутствие контактов или внешние анкеты
работодателя не определяются. При обычной ошибке подробностей сохраняется причина,
сбор продолжается; при капче или ограничении HH требуется вмешательство пользователя.
Повторная карточка и неудачная загрузка не стирают ранее сохранённые подробности.

Контакты не загружаются. Зарплата не разбирается на числовые границы и валюту.
Оценки нейросети и отклики выполняются отдельными действиями.

На карточке резюме два поля:

- **Что искать по этому резюме** — поисковый запрос, как в строке поиска hh.ru
  («Python разработчик»). У каждого резюме свой.
- **Расскажите про свой опыт** — свободный текст без ограничения длины: проекты,
  детали задач, чем гордитесь, чего не хотите. Всё, чего нет в резюме.

Резюме можно держать несколько, активное — одно; по нему работает весь цикл.

### 4. Собрать профиль

Там же кнопка «Собрать профиль» и выпадашка с моделью. Профиль — это сжатый
текст из резюме и вашего рассказа; именно он уходит в нейросеть при оценке
вакансий и написании писем.

Считается один раз, поэтому здесь уместна тяжёлая модель. Пересобирается сам,
когда вы правите рассказ об опыте.

### 5. Запустить цикл

Панель сверху: выберите вариант и нажмите **Старт**.

| Вариант | Что делает |
| --- | --- |
| Собрать вакансии | Проходит страницы поиска по запросу активного резюме |
| Оценить соответствие | Прогоняет неоценённые вакансии через нейросеть |
| Откликнуться по порогу | Отклик на всё выше порога, чего ещё не отправляли |
| **Полный цикл** | Сбор → оценка → отклики (этапы включаются в настройках) |
| Обновить резюме | Поднимает резюме в поиске hh.ru |
| Войти в hh.ru | Ручной вход в аккаунт |
| Собрать профиль | Пересборка профиля кандидата |

Внизу экрана — журнал текущей задачи, обновляется вживую. **Стоп**
останавливает, второе нажатие прерывает принудительно.

Отдельной строкой — **имитация активности**: запускается параллельно и не мешает
основной задаче.

## Ежедневное использование

**Вкладка «Вакансии»** — всё собранное с оценками и обоснованиями. Фильтры:
оценка от, только оценённые, без отклика, поиск по названию, а если резюме
несколько — «найдено под резюме X». Отмечайте галочками и жмите «Откликнуться
на выбранные», если не доверяете автоматике.

**Вкладка «Отклики»** — на что откликнулись, с какой оценкой и каким письмом.
Там же показано, удалось ли отправить сообщение в чат работодателя. Если чат
выключен для вакансии или отправка не подтвердилась, отклик остаётся успешным,
а причина показывается отдельно.
Письмо разворачивается по клику: удобно смотреть, что генерит нейросеть, и
докручивать инструкцию в настройках.

**Вкладка «Прогоны»** — история задач: что запускалось, вручную или по
расписанию, чем закончилось.

**Расписание** (настройки → «Расписание») — три независимых цикла:
сбор-оценка-отклики, имитация активности и обновление резюме, у каждого свой
интервал. Отклики по расписанию уходят, только если режим откликов `auto`.

## Настройки

Вкладка **«Настройки»**. Значения из `configs/*.yaml` — стартовые, изменённое в
интерфейсе хранится в базе и имеет приоритет. Редко нужное спрятано под
«Тонкую настройку».

| Раздел | Что там важного |
| --- | --- |
| Поиск и сбор | Режим чтения страницы, параметры прокрутки; сбор без лимита страниц |
| Ограничение нагрузки | Пауза между страницами (1 с), потолок запросов в минуту (100) |
| Оценка соответствия | **Порог для отклика**, размер пачки, инструкция для нейросети |
| Отклики | **Режим `manual`/`auto`**, лимит откликов за прогон, пауза между ними |
| Профиль кандидата | Модель для сборки профиля, длина, инструкция |
| Сопроводительное письмо | Включение, модель, когда прикладывать, длина, инструкция |
| Имитация активности | Длительность, паузы, заходить ли в вакансии |
| Расписание | Интервалы трёх циклов |
| Нейросеть | Стандарт API, URL, ключ, модель |
| Браузер | Видимый или headless, закрывать лишние вкладки |

Три модели настраиваются раздельно: рабочая (оценка), для профиля и для писем.
У профиля и писем пустое значение означает «та же, что для оценки».

Зелёная лампочка в панели и в настройках показывает связь с нейросетью.

## Как устроено

```text
main.py web
   │
   ├── веб (FastAPI + Jinja + htmx)     страницы, настройки, живой журнал по SSE
   ├── очередь main        сбор → оценка → отклики, вход, обновление резюме
   ├── очередь activity    имитация активности, параллельно
   ├── очередь profile     сборка профиля, без браузера
   ├── планировщик         три независимых цикла
   └── рейт-лимитер        общий на все очереди
```

Один Camoufox в Docker и общая сессия HH; у каждой задачи своя вкладка. Данные — SQLite
(`data/career_agent.db`) или PostgreSQL.

## Данные и приватность

База и сессия хранятся рядом в каталоге данных (`data/` по умолчанию) и не попадают в Git:

| Файл | Что внутри |
| --- | --- |
| `career_agent.db` | Вакансии, оценки, отклики, письма, резюме, настройки, ключ от нейросети |
| `hh-session.json` | Cookies, localStorage и IndexedDB сессии HH |
| `hh-build.log` | Журнал первоначальной сборки локального браузера |

Отпечаток Camoufox хранится в отдельном Docker volume. Для каждой папки данных
создаётся свой контейнер; порты браузера и VNC доступны только с самого компьютера.

Текст профиля уходит вашему провайдеру нейросети при каждой оценке вакансии.
Если в профиле есть контакты и это нежелательно — уберите упоминание контактов
из инструкции в разделе «Профиль кандидата» и пересоберите профиль.

Локальный запуск из исходников выводит личную ссылку; Windows-ярлык открывает её сам.
Ссылка выдаёт ограниченную по времени сессию панели с защитой действий от CSRF.
Для доступа с телефона используйте ту же ссылку с IP компьютера и `WEB_HOST=0.0.0.0`,
либо Docker Compose с паролем панели. Для публичного сервера используйте HTTPS.

## Если что-то не так

**Лампочка красная.** Мост с нейросетью не поднят или неверный ключ. Наведите
курсор — там причина; кнопка «проверить» перепроверяет.

**«Не задан поисковый запрос».** Заполните поле на карточке активного резюме.

**Сбор ничего не находит.** Проверьте, что вошли в hh.ru и что запрос вообще
что-то выдаёт на сайте. Если появилась капча — решите её в окне HH внутри панели.

**Отклик не отправился.** Смотрите журнал: `skipped_questions` — анкета
работодателя, такие пропускаются намеренно; `failed` с «кнопка отправки
осталась заблокированной» — форма требует чего-то ещё.

**Не помню, что оно натворило.** Вкладка «Прогоны» плюс журнал внизу экрана.
