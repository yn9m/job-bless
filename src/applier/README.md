# Отклики

## Порядок действий на вакансии

1. Открыть страницу вакансии (через рейт-лимитер — не чаще заданного интервала).
2. Уже откликались? → `already_applied`.
3. Опциональная перепроверка нейросетью по полному тексту вакансии
   (`apply.recheck_with_llm`) → при низкой оценке `skipped_low_score`.
4. Нажать «Откликнуться».
5. **Вопросы работодателя** (тесты, анкеты) → `skipped_questions`.
6. **Сопроводительное письмо** — не вопросы: генерируем и продолжаем отклик.
7. Подтвердить отправку, проверить результат → `applied`.

## Сопроводительное письмо

Раньше любая `textarea` в модалке считалась анкетой, поэтому вакансии с
сопроводительным письмом просто пропускались. Теперь поле письма
распознаётся отдельно (по `data-qa`, содержащему `letter`), и анкетой считается
только **другое** незаполненное текстовое поле.

Что происходит, когда поле письма найдено:

| Ситуация | Поведение |
| --- | --- |
| Генерация включена, письмо написано | заполняем и откликаемся, текст письма сохраняется в отклике |
| Нейросеть не ответила, задан запасной текст | отправляем запасной текст |
| Нейросеть не ответила, запасного текста нет, письмо обязательное | `skipped_questions` с причиной |
| То же, но поле необязательное | откликаемся без письма |
| Генерация выключена, письмо обязательное | `skipped_questions` |

Режим `cover_letter.when`:
`required` — писать только когда hh.ru показывает поле сам;
`always` — раскрывать и необязательное поле «добавить сопроводительное».

Текст чистится перед отправкой: убираются markdown, плейсхолдеры вида
`[Ваше имя]`, приветствия и подписи, длина обрезается по границе предложения
до `cover_letter.max_chars`. Слишком короткий ответ модели считается неудачей —
лучше пропустить вакансию, чем отправить огрызок.

Отправленное письмо целиком попадает в `response_text` отклика, поэтому его
видно на вкладке «Отклики».

## Селекторы: проверены на реальной странице

Разметка снята с сохранённой страницы вакансии (текущий макет `magritte`,
не `bloko`):

| Что | Селектор |
| --- | --- |
| Форма отклика | `form#RESPONSE_MODAL_FORM_ID` (`name="vacancy_response"`) |
| Поле письма | `[data-qa="vacancy-response-popup-form-letter-input"]` |
| Кнопка отправки | `[data-qa="vacancy-response-submit-popup"]` |
| Закрыть модалку | `[data-qa="response-popup-close"]` |

Два вывода из разметки:

1. **Обязательность письма** hh.ru не помечает атрибутом — вместо этого держит
   кнопку отправки `disabled`, пока поле пустое. Пустое письмо плюс
   заблокированная кнопка и есть «письмо обязательное».
2. **`vacancy-response-question_*` — это не анкета работодателя**, а `<div>`-
   подсказки «о чём спросить». Инпутов в форме отклика ровно один — письмо.

Клик по заблокированной кнопке ничего не делает, а раньше это засчитывалось как
успешный отклик. Теперь бот ждёт, пока кнопка станет активной (до 6 секунд), и
если она так и осталась заблокированной — отклик помечается `failed` с причиной,
а не «отправлен». После заполнения письма посылаются настоящие события клавиш:
программная подстановка текста может оставить форму в состоянии «поле пустое».

## Где посмотреть письма

Отправленное письмо хранится в отдельной колонке `vacancy_applications.cover_letter`
и разворачивается прямо в таблицах: на вкладке «Отклики» и в колонке отклика на
вкладке «Вакансии». Это чтобы можно было ретроспективно оценивать, что пишет
нейросеть, и докручивать промпт в настройках.

## Настройки

Раздел «Сопроводительное письмо»: включение, режим, максимальная длина,
инструкция для нейросети и запасной текст (в тонкой настройке).
