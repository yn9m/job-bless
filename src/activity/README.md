# Имитация активности

Отдельный модуль: сбор вакансий и «быть активным» — разные задачи, и они
работают **параллельно**, в своих вкладках и со своими настройками.

| | Сбор вакансий | Имитация активности |
| --- | --- | --- |
| Цель | распарсить карточки | держать аккаунт живым |
| Прокрутка | не нужна: hh.ru сам дорисовывает все 50 карточек за ~4 с после загрузки, сбор просто ждёт, пока список перестанет расти | и есть весь смысл модуля |
| Темп | так быстро, как позволяет лимит | медленно, с паузами |
| Результат | вакансии в базе | ничего не сохраняется |
| Очередь (lane) | `main` | `activity` |
| Расписание | `schedule.*` | `schedule.activity_*` |

## Очереди задач

[`TaskManager`](../web/tasks.py) держит две независимые очереди. В `main`
по-прежнему одна задача за раз: сбор, оценка и отклики делят один рабочий
процесс браузера и не должны накладываться. Очередь `activity` живёт рядом —
её можно запустить и остановить, не трогая основную задачу.

Общий у них только [рейт-лимитер](../ratelimit_README.md): суммарный поток
запросов к hh.ru не растёт от того, что задач стало две.

## Что делает

Открывает страницу (по умолчанию — текущий поисковый запрос), прокручивает её
случайными шагами с паузами, иногда листает вверх. Опционально заходит в
случайные вакансии и «читает» их несколько секунд — это настраивается
отдельно, потому что расходует лимит запросов.

Ничего не парсится и не сохраняется: модуль намеренно не знает про базу.

## Настройки

Раздел «Имитация активности»: адрес, длительность прогона, диапазон пауз,
открывать ли вакансии и с какой вероятностью; в «тонкой настройке» — шаги
прокрутки, вероятность прокрутки вверх, время чтения вакансии.

Запуск: кнопка «Запустить параллельно» в панели задач или расписание
(`schedule.activity_enabled` + свой интервал).
