# Веб-интерфейс

Один процесс: FastAPI + Jinja + htmx, фоновые задачи (браузер) и планировщик.

```bash
make web-local     # http://127.0.0.1:8080
```

## Страницы

| Путь | Что делает |
| --- | --- |
| `/` | Переход на основную страницу `/actions` |
| `/actions` | Необходимые настройки (вход в hh.ru, выбор резюме, нейросеть), все действия, состояние задач и журнал |
| `/vacancies` | Таблица вакансий с оценкой, обоснованием и статусом отклика; фильтры (оценка от, только оценённые, без отклика, поиск, сортировка); выбор галочками и «Откликнуться на выбранные» |
| `/applications` | Отклики бота: когда, на что, статус (`applied` / `skipped_questions` / `skipped_low_score` / `failed`), оценка и комментарий |
| `/resume` | Автоматический импорт резюме из аккаунта hh.ru, обновление всех резюме, выбор активного, опыт, образование, сертификаты и подтверждённые навыки |
| `/runs` | История прогонов: задача, ручной/по расписанию, статус, результат или ошибка |
| `/settings` | Общие настройки: порог отбора вакансий, ограничение нагрузки и браузер |

Панель и журнал находятся только на странице «Действия», доступной из верхнего меню.
Остальные страницы сразу показывают своё содержимое. После ручного запуска импорта
резюме, обновления профиля или откликов из списка вакансий открывается «Действия».

Действия показаны сеткой закруглённых карточек: четыре в ряд на широком экране,
две или одна на узком. Каждая карточка содержит описание и кнопку ▶; при запуске
она меняется на ■, которая останавливает задачу. Паузы с продолжением нет.
Работающая карточка выделяется, недоступные приглушены и показывают причину блокировки.
Шестерёнка открывает настройки поиска, нейросети или последовательности действий.

Сверху находится секция «Необходимые настройки»: аккаунт hh.ru, выбор активного
резюме и подключение к нейросети. Резюме выбирается прямо в карточке; во время
основного действия переключение заблокировано. Настройки нейросети открываются
в отдельном окне и сохраняются независимо от остальных параметров.
Сбор и выгрузка доступны без импорта; резюме нужно для оценки и откликов.
Сбор вакансий работает без входа в hh.ru, в том числе после выхода из аккаунта
и при запуске по расписанию. Последовательность без отправки откликов тоже
не требует входа в HH. Проверки CAPTCHA и ограничений доступа самого сайта сохраняются.
Повторный сбор просматривает выдачу до конца, но не открывает отдельные вакансии,
у которых уже сохранено полное описание или подтверждён архив. Карточки без
подробностей, включая предыдущие неудачные попытки, остаются в очереди загрузки.
Все найденные карточки связываются с текущим поиском и резюме, включая уже известные.
На подробности одной вакансии отводится до трёх попыток и 90 секунд суммарно;
ошибка сохраняется, после чего сбор продолжается со следующей вакансии.
После трёх неудачных попыток загрузить страницу выдачи сбор завершается ошибкой,
сохраняя уже записанные результаты. CAPTCHA и ограничения доступа требуют вмешательства.
Прогресс показывает новые и уже известные вакансии, загруженные и пропущенные
подробности, ошибки. Список и счётчик вакансий обновляются после обработки страницы
выдачи; выбранные вакансии и раскрытые описания сохраняются до ручного обновления.
Поиск, оценка, отклики, вход и поднятие резюме делят основную очередь; обновление описания опыта может выполняться параллельно.
Кнопка остановки управляет только очередью своей карточки. Запуск последовательности
отмечается отдельно от сбора, в том числе при старте по расписанию.

Поле «Какую работу ищете» находится в карточке «Искать вакансии» и сохраняется при изменении. Кнопка запуска использует текущий текст поля. Окно «Настроить поиск» содержит только параметры загрузки выдачи. Без резюме запрос
сохраняется отдельно в `search.query`; с активным резюме используется его собственный
запрос. Пустой запрос блокирует сбор. Последовательность только со сбором также
доступна без резюме, в том числе по расписанию.
«Настроить действия» открывает выбор этапов и сохранение без перехода
в настройки. Выбор оценки включает `matching.enabled`, выбор отправки — режим
`apply.mode=auto`; это поясняется в окне. Этапы используются также расписанием.
Сохранение меняет только эти параметры и флаги этапов; остальные настройки сохраняются.

В заголовке страницы «Вакансии» кнопка «Скачать CSV · N»
выгружает весь результат текущих фильтров, со всех страниц и в выбранном порядке.
Без фильтров выгружается весь список. Галочки используются только для откликов.
Число на кнопке — количество вакансий в файле, включая остальные страницы.
Фильтры и сортировка применяются автоматически; поиск и минимальная оценка —
через 400 мс после ввода. Список и счётчик обновляются без перезагрузки страницы.
`GET /vacancies/export` принимает те же фильтры, что список. Файл содержит ссылки,
зарплаты, условия, сохранённый текст карточек, навыки, оценки и статусы откликов.
Кодировка UTF-8 с BOM, разделитель — точка с запятой, заголовки на русском.
Формулы из текста карточек экранируются для безопасного открытия в Excel.

## Индикатор нейросети

Лампочка есть в карточке «Нейросеть» на странице «Действия» и в её окне настроек: точка, текст,
модель, задержка, кнопка «проверить». Зелёная — связь есть, красная — нет
(с причиной: ключ отклонён, сервер недоступен, таймаут, лимит), серая — выключена.

Проверка ([`src/llm/health.py`](../llm/health.py)) дёргает список моделей — без
расхода токенов, с коротким таймаутом и без ретраев. Опрос — раз в 10 секунд
(`LLM_POLL_SECONDS`), кэш чуть короче интервала, поэтому несколько лампочек на
странице делят одну проверку. Сохранение настроек сбрасывает кэш.

> Важно: фрагмент, который возвращает `/actions/llm-health`, **не** содержит
> `hx-trigger="load"` — иначе каждая подстановка мгновенно запускала бы новый
> запрос, и эндпоинт получал бы десятки запросов в секунду.

Поле «Модель» — выпадающий список, который подгружается с самого эндпоинта
(`GET /actions/llm-models` → `list_models()`, тот же кэш, что у лампочки).
Если список получить не удалось, поле остаётся текстовым, а кнопка рядом
пробует запросить его снова. Своё значение, которого нет в списке, не теряется.

Статика отдаётся с `Cache-Control: no-cache` и ссылками вида `app.css?v=<mtime>` —
иначе браузер держит старую таблицу стилей и страница выглядит «без CSS».

## Остановка задач

«Стоп» работает в три слоя, потому что браузерные вызовы могут висеть дольше
любого чекпоинта:

1. хуки остановки (`ctx.on_stop`) срабатывают в момент нажатия — сборщик
   прерывает скролл сразу, а не в конце страницы;
2. кооперативные проверки `ctx.raise_if_stopped()` между шагами;
3. через 4 секунды (или по второму нажатию — кнопка становится
   «Остановить принудительно») задача отменяется жёстко.

## Как это устроено

```text
main.py web  →  src/web/app.py (lifespan: БД → SettingsService → TaskManager → Scheduler)
                 ├── routes/pages.py    HTML-страницы
                 ├── routes/actions.py  запуск задач, настройки, резюме, SSE (/actions/events)
                 ├── tasks.py           одна задача за раз, лог, прогресс, стоп, подтверждение
                 ├── jobs.py            collect / score / apply / resume_import / login / pipeline
                 └── scheduler.py       периодический запуск pipeline
```

Поиск настраивается одним полем «Что ищем» — это параметр `text` в URL hh.ru.
Остальные фильтры (город, опыт) берутся из `hh_autoscroller.search_url` в YAML,
который служит шаблоном: меняется только запрос, прочие параметры сохраняются.

Настройки: YAML — дефолты, таблица `app_settings` — переопределения.
Схема полей объявлена в [`src/settings.py`](../settings.py) (`FIELDS`); чтобы добавить
настройку, достаточно дописать туда `SettingField` — форма и валидация появятся сами.
Флаг `advanced=True` прячет поле в спойлер «Тонкая настройка» (так убраны параметры
скролла); спойлер раскрывается сам, если какое-то значение внутри отличается от дефолта.

`SettingsService` отдаёт готовые дата-классы (`browser_config()`, `scroller_config()`,
`llm_config()`), поэтому сервисы не знают, откуда пришло значение.

## Живые обновления

`/actions/events` — SSE-поток: `snapshot` (лог текущей задачи при подключении),
`log`, `progress`, `started`, `finished`, `stopping`.
[`static/app.js`](static/app.js) дописывает журнал, двигает прогресс-бар и
перерисовывает панель через htmx. htmx лежит локально (`static/htmx.min.js`) —
интерфейс работает без интернета.

## Вход в hh.ru

Кнопка «Открыть браузер» показывает Camoufox из Docker прямо в панели и автоматически
проверяет вход (до 15 минут); «Я вошёл» запускает повторную проверку. Сессия сохраняется
в `hh-session.json` рядом с SQLite. Вход и фоновые задачи используют один BrowserContext.
Локально контейнером управляет приложение; на сервере — Docker Compose.
[Запуск и восстановление сессий](../../docs/server.md).

«Сменить аккаунт» сначала запрашивает подтверждение, затем открывает отдельное
окно входа. До успешной проверки нового аккаунта рабочая сессия и её сохранённая
копия остаются прежними. «Стоп» отменяет смену; ошибка при переносе новой сессии
возвращает старые cookies. Остановка последующего импорта резюме не отменяет уже
подтверждённый вход.

## Очереди задач

Две независимые очереди: `main` (поиск, оценка, отклики, вход, поднятие
резюме — по одной задаче за раз) и `profile`
(описание опыта), которая работает параллельно.
«Стоп» действует на конкретную очередь.

## Расписание

Два независимых цикла, каждый со своим интервалом:

| Цикл | Настройки | Очередь |
| --- | --- | --- |
| Сбор → оценка → отклики | `schedule.enabled`, `schedule.interval_minutes`, флаги этапов | `main` |
| Обновление резюме | `schedule.resume_touch_enabled`, `schedule.resume_touch_interval_hours` | `main` |

Отклики по расписанию уходят только если `apply.mode = auto` — в ручном режиме
этап пропускается с записью в журнал. Если очередь занята, запуск не теряется,
а откладывается на 5 минут.

## Остановка сервера

Ctrl+C завершает процесс за ~2 секунды даже с открытыми вкладками, без трейсбека.
Поток журнала (SSE) бесконечен по своей природе, поэтому uvicorn ждал бы его вечно
(«Waiting for connections to close»); обработчик сигнала в
[`serve()`](app.py) выставляет `app.state.shutting_down`, потоки закрываются
сами на ближайшем heartbeat (3 с), а `timeout_graceful_shutdown` в 5 секунд
страхует остальное.

`KeyboardInterrupt` перехватывается в [`main.py`](../../main.py) (`run()`) — это
штатный способ остановки, а не авария. Там же сторожевой таймер: если
подвисший не-демон поток (например, недобитый драйвер Playwright) не даёт
интерпретатору выйти, процесс завершается принудительно через 3 секунды.
Чтобы драйвер не оставался в живых при жёсткой отмене задачи, `BrowserConnector`
в `_cleanup` доводит закрытие до конца даже под `CancelledError`.

## Доступ

По умолчанию слушает `127.0.0.1` без авторизации. Если открываете наружу,
задайте `web.token` в конфиге (или `WEB_TOKEN`): первый заход по
`?token=...` ставит cookie, без токена — 401.

«Настроить отклики» на карточке отправки открывает общее окно: порог оценки,
лимит и пауза, перепроверка нейросетью, сопроводительное письмо и режим запуска.
Это те же значения, что на странице настроек; порог также используется в счётчиках
подходящих вакансий. Сохранение не запускает задачу и изменяет только поля этого
окна. При ошибке валидации изменения не применяются, введённые значения остаются
в форме. Неиспользуемый переключатель `apply.skip_questions` в окно не включён.

Функция фонового просмотра удалена: кнопка, HTTP-запуск, настройки и цикл расписания недоступны. Старые записи прогонов сохраняются в истории.
