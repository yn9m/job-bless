# Резюме, поисковый запрос и профиль кандидата

Резюме — не просто текст для сравнения, а единица настройки: у каждого свой
поисковый запрос, свой рассказ об опыте и свой собранный профиль.

```text
резюме с hh.ru ──┐
                 ├── профиль кандидата ──> оценка вакансий
«расскажите про  ┘   (собирается один раз)   сопроводительные письма
 свой опыт»                                  ответы на вопросы работодателя
```

## Что задаётся на карточке резюме

| Поле | Зачем |
| --- | --- |
| Что искать по этому резюме | Поисковый запрос hh.ru. Раньше был один на всё приложение, теперь у каждого резюме свой |
| Расскажите про свой опыт | Свободный текст: проекты, детали, чего нет в резюме. Объём не ограничен |
| Профиль кандидата | Собирается из двух текстов выше, показывается на карточке |

Активное резюме одно: сбор, оценка и отклики работают по нему. Переключил
активное — следующий прогон идёт по его запросу и его профилю.

Каждый прогон сбора запоминает, для какого резюме он был (`search_runs.resume_id`),
поэтому в списке вакансий есть фильтр «найдено под резюме X». Сами вакансии в
базе не дублируются, оценки и так хранятся парой (вакансия, резюме).

## Профиль кандидата

[`profile.py`](profile.py) сжимает резюме плюс контекст в один связный текст.
Смысл: в сравнение с каждой вакансией уходит именно он, а не сырой текст резюме
— это и дешевле по токенам, и точнее, потому что в профиле есть то, чего на
hh.ru нет.

Модель для сборки выбирается **отдельно** (раздел настроек «Профиль кандидата»):
задача выполняется редко, поэтому здесь уместна тяжёлая модель, а на оценку
вакансий пусть работает быстрая. У профиля свои лимит токенов и таймаут.

Если исходников много (больше ~14 000 символов), текст сжимается по частям, а
потом части сводятся в один профиль — так ничего не теряется на длинных
рассказах об опыте.

Пересборка: автоматически при изменении текста «расскажите про свой опыт» и по
кнопке «Пересобрать профиль». Профиль помечается устаревшим, если резюме или
контекст изменились после сборки. Считается в собственной очереди задач — она не
трогает браузер, поэтому не ждёт сбор и отклики.

Пока профиль не собран, всё работает по-старому: в модель уходит
структурированное резюме плюс сырой текст с обрезкой.

## Разбор резюме с hh.ru

Смотри [про секции](#) ниже — разбор по заголовкам, а не по CSS-селекторам.

```text
BrowserConnector → страница резюме → innerText → parse_sections() → Resume → БД
                                        ↘ CSS-селекторы (title, имя, зарплата, город)
```

Разметка hh.ru отличается у публичного просмотра и у собственного профиля и
меняется со временем, поэтому `data-qa`-селекторы регулярно перестают попадать.
Текст страницы устроен стабильно: заголовки разделов идут отдельными строками.
[`sections.py`](sections.py) режет текст по ним (`Опыт работы`, `Навыки`,
`Образование`, `О себе`, `Сертификаты`), обрывая раздел на промо-блоках hh.ru и
выкидывая кнопки интерфейса.

`ResumeService.backfill_sections()` перечитывает уже сохранённый `raw_text` у
резюме, импортированных прежней версией, — переимпорт с hh.ru не нужен.
